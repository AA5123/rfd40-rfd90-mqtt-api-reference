Connecting a Zebra Handheld RFID Device using 123RFID Desktop

Introduction​

This guide provides step-by-step instructions to discover, connect, and configure a Zebra handheld RFID reader (RFD40/RFD90) using the 123RFID Desktop utility. It covers establishing a direct connection via Bluetooth or USB, configuring Wi-Fi connectivity, setting up an MQTT endpoint, and verifying end-to-end communication with an MQTT client.

123RFID Desktop is a Windows utility that simplifies Zebra RFID reader deployment without requiring expert-level configuration knowledge.

Prerequisites​

  • Zebra handheld RFID device (e.g., RFD40 or RFD90), charged and in pairing mode.
  • Windows PC with the 123RFID Desktop application installed and Bluetooth enabled.
  • Wi-Fi network credentials (SSID, protocol type, passkey).
  • Access to an MQTT broker (see Phase 3).
  • Reader serial number (printed on the device label).

Phase 1: Discover and Connect the Reader​

Before configuring Wi-Fi or MQTT, establish a direct connection between the reader and your PC.

  1. Launch the Application: Open 123RFID Desktop. The Welcome screen appears.
  2. Initiate Discovery: Click FIND READERS on the main screen.
  3. Select Connection Type: In the Reader Discovery screen, click the Bluetooth icon (or USB for a cabled connection) to scan for devices.
  4. Choose Your Device: In the "Add a device" pop-up, select your handheld reader. Verify the displayed serial number matches the one printed on the device.
  5. Confirm Selection: Click Next.
  6. Connect: Locate your device in the Available Readers list and click the green CONNECT button.
  7. Verify Connection: The reader moves from the bottom list to the Connected Readers section at the top.

Phase 2: Configure Wi-Fi Connectivity​

The reader needs a stable network connection for MQTT and other network-dependent protocols.

  1. Open Configuration: Click the Configure icon (gear symbol) in the left navigation panel.
  2. Select Reader: In the Reader Configuration window, click the picture of the connected reader.
  3. Edit Configuration: Click Edit Configuration on Reader.
  4. Navigate to Communication: From the left menu, select Communication. The Wi-Fi Configuration window opens by default.
  5. Add Network: Select Scan and Choose Network, then pick your SSID from the dropdown. For hidden networks, use Enter SSID.
  6. Enter Credentials: Choose the protocol (e.g., WPA2_Personal_CCMP) and enter the passkey.
  7. Connect to Wi-Fi: Click Add, then Connect.
  8. Verify Network: Under Existing Connection, confirm the SSID, IP address, MAC address, and Status: Connected.

Phase 3: Set Up an MQTT Broker​

Before configuring the endpoint, ensure an MQTT broker is running and reachable from the reader's Wi-Fi network.

  1. Choose your broker: Select a broker appropriate for your environment. Broker setup is outside the scope of this guide — refer to the official documentation for your chosen broker:
    • Eclipse Mosquitto (local/on-prem, ideal for testing): mosquitto.org/documentation
    • HiveMQ / EMQX (enterprise alternatives): refer to respective vendor documentation.
  2. Start the broker: Ensure the broker is running and listening on the correct port (1883 for MQTT, 8883 for MQTTS) before proceeding.
  3. Gather your connection details: Keep the following ready before moving to Phase 4:
    • Broker URL or IP address.
    • Port (1883 for MQTT, 8883 for MQTTS).
    • Credentials (username/password, if authentication is enabled).
    • Certificates — CA certificate and device cert/key, required for MQTTS connections.

Tip: Verify the broker is reachable from the reader's network segment using MQTTX or mosquitto_sub from another device on the same Wi-Fi before configuring the reader.

Phase 4: Add an MQTT Endpoint​

Configure the MQTT broker connection on the reader using the End Point Configuration screen.

  1. Navigate to End Point Tab: In the Communication section, click the End Point tab.
  2. Create New Endpoint: Click New on the right side of the screen.
  3. Fill in Configuration Details: Enter the connection details using the reference table below.
FieldDescription
TypeSelect MQTT (other options: SOTI, MDM).
ProtocolMQTT (plaintext, port 1883) or MQTTS (TLS, port 8883).
URLBroker hostname or IP address.
Port1883 for MQTT, 8883 for MQTTS.
Keep AliveHeartbeat interval in seconds to maintain the connection.
Tenant IDPrefix applied to all MQTT topics (e.g., zebra).
Clean SessionWhen checked, discards queued messages on reconnect.
Host VerifyValidates the broker's TLS certificate hostname. Required for MQTTS in production.
Command TopicUser-configured middle segment for the publish topic (e.g., CTRL/clients/cmnd).
Command Response TopicUser-configured middle segment for command responses (e.g., CTRL/clients/resp).
Alert & Event TopicUser-configured middle segment for alerts/events (e.g., CTRL/clients/event).
Data Event TopicUser-configured middle segment for tag data events (e.g., DATA/clients/data1event).

Note: Topic fields are optional. If left blank, defaults are auto-populated when you click Add.

  1. Add Endpoint: Click Add. The new endpoint appears in the endpoint list at the bottom.
  2. Activate Endpoint: Tick the Activate checkbox in the row for your new endpoint.
  3. Verify Status: Under Endpoint Status, click Refresh. The status should read Connected.
  4. Save: Click Save to commit the configuration to the reader.

Disconnected? Common causes: unreachable broker, wrong port, missing CA certificate for MQTTS, or firewall blocking outbound traffic.

Phase 5: Test the Connection Using MQTTX​

Verify the reader is publishing and receiving messages correctly using MQTTX as the test client.

Before you start, gather:

  • Broker URL, port, and credentials (same as configured in Phase 4).
  • Tenant ID and user-configured topic paths from your endpoint configuration.
  • Reader serial number (visible in 123RFID Desktop under the connected reader's details).

Topic Structure​

RFD40/RFD90 topics follow this pattern:

<Tenant ID>/<User Configured Topic>/<Device Serial No>

Publish Topic (Reader subscribes to receive commands)​

Only one publish topic is supported — the host application publishes commands here, and the reader receives them.

PurposeFormatExample
Commands<tenant>/<cmd-topic>/<serial>zebra/CTRL/clients/cmnd/RFD40-212735201D0053

Subscribe Topics (Reader publishes to these; host subscribes)​

The reader publishes to three subscribe topics for responses, events, and data.

TypeFormatExample
Command Response<tenant>/<resp-topic>/<serial>zebra/CTRL/clients/resp/RFD40-212735201D0053
Alert & Event<tenant>/<event-topic>/<serial>zebra/CTRL/clients/event/RFD40-212735201D0053
Data Event (tag reads)<tenant>/<data-topic>/<serial>zebra/DATA/clients/data1event/RFD40-212735201D0053

Tag reads: When the reader is scanning, RFID tag data streams in real time to the Data Event topic. Pull the trigger over a tagged item to generate data — it will appear on <tenant>/<data-topic>/<serial> (e.g., zebra/DATA/clients/data1event/RFD40-212735201D0053).

Note: The middle segment (e.g., CTRL/clients/cmnd) is fully user-configurable in Phase 4. Examples above use the conventional defaults.

Steps​

  1. Install MQTTX: Download from mqttx.app (Windows, macOS, Linux). Install and launch the application.
  2. Create a new connection:
    • Click + New Connection.
    • Name: any label (e.g., RFD40-Test).
    • Host: broker URL or IP (e.g., 192.168.1.50).
    • Port: 1883 (MQTT) or 8883 (MQTTS).
    • Username / Password: if authentication is enabled.
    • For MQTTS: enable SSL/TLS and upload the CA certificate.
    • Click Connect.
  3. Subscribe to all reader topics using a multi-level wildcard:
    • Click + New Subscription.
    • Topic: <tenant>/# (e.g., zebra/#) to capture every topic published by the reader.
    • QoS: 0 or 1.
    • Click Confirm.
  4. Send a test command and verify the response:
    • In the message composer, set Topic to the full publish topic, e.g., zebra/CTRL/clients/cmnd/RFD40-212735201D0053.
    • Set payload format to JSON.
    • Paste a test command payload — get_version is a safe first call (see the API Reference).
    • Click Send.
    • Confirm a response arrives on the Command Response topic (zebra/CTRL/clients/resp/<serial>).

What Success Looks Like​

  • Tag reads stream into the Data Event topic in real time.
  • Command-response round-trip completes in under a second on a healthy network.
  • Alerts and lifecycle events appear on the Alert & Event topic.
  • No "Disconnected" flapping in 123RFID Desktop's Endpoint Status.

Your Zebra handheld RFID reader is now connected to the network, communicating with your MQTT broker, and verified end-to-end.
